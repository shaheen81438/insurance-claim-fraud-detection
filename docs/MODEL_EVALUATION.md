# Model Evaluation

This report was generated by the reproducible training pipeline in
`src/modeling.py` using `random_state=42`.

## Evaluation protocol

- The original dataset was split once into 800 training and 200 held-out test
  rows using stratification.
- Candidate pipelines were evaluated with five-fold stratified cross-validation
  on the training partition only.
- Every fold fitted feature engineering, imputation, scaling, and encoding only
  on that fold's training rows.
- Candidate ranking used mean average precision (PR-AUC), with cross-validation
  variability considered in the comparison.
- A validation split inside the training partition selected calibration and the
  operating threshold. The held-out test partition was not used for either.

Confusion matrix at the frozen threshold 0.18: true negatives 121, false
positives 30, false negatives 7, true positives 42.

## Interpretation

The selected threshold prioritizes finding fraud: it catches 42 of 49 fraud
claims in the held-out test partition, while creating 30 false-positive review
cases. A false negative represents a missed potential fraud case; a false
positive consumes investigator capacity. The appropriate operating point depends
on real investigation capacity and costs, which were not supplied here.

These results are from one small public-style dataset and one held-out split.
They do not establish real-world fraud-detection effectiveness or causal
relationships.
